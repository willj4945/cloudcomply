# Security model

cloudcomply is a security tool and is often run with privileged read access to an organization's security data, so its own footprint should be small and easy to audit.

## What cloudcomply does

| Property | Detail |
|---|---|
| **Read-only AWS access** | Calls only `securityhub:GetFindings`, `organizations:DescribeOrganization`, `organizations:ListAccounts` and `sts:GetCallerIdentity`. See [IAM permissions](aws/permissions.md). |
| **Standard credential chain** | Credentials come only from the AWS SDK default chain. cloudcomply never reads, stores, caches or logs credential material, and has no flags for passing keys. |
| **No persistence** | Writes no config, cache, log or state files. Output goes only to stdout/stderr, and only when you redirect it does it reach disk. |
| **No telemetry** | The only network traffic is HTTPS to AWS service endpoints. No analytics, update checks or crash reporting. |
| **Terminal-safe output** | Text from Security Hub findings (which third-party integrations can write via `BatchImportFindings`) has control characters stripped, so ANSI/OSC escape sequences can't run in your terminal. |
| **Static binary** | Built with `CGO_ENABLED=0`, with no dynamic linking or runtime plugin loading. |
| **Bounded runtime** | AWS calls stop after 30 seconds, so a stuck call can't hang a pipeline indefinitely. |

## Handling cloudcomply output

Reports reveal your organization's control weaknesses: which controls fail, how badly and in how many accounts. Treat them as **sensitive**. They may be CUI in DoD contexts.

- Store reports where you store other assessment evidence, encrypted and access-controlled.
- Don't commit them to Git. This repo gitignores `reports/`, `output/` and `*.report.*`.
- Don't upload them as artifacts in public CI repositories. See [CI/CD](usage/automation.md#github-actions-oidc-no-long-lived-keys).
- Error messages from AWS can contain your account ID and role ARN. Redact them before posting in a public issue.

## Supply chain

| Control | Implementation |
|---|---|
| Signed releases | `checksums.txt` is signed with Sigstore cosign keyless signing, bound to this repository's release workflow identity. See [Verifying releases](verifying-releases.md). |
| SBOM | CycloneDX SBOM generated by Syft for every release binary |
| Reproducible inputs | `go.sum` pins every module hash. `go mod verify` runs before release builds. |
| Static analysis | `gosec` (SARIF in GitHub code scanning) and `golangci-lint` on every PR |
| Dependency vulnerabilities | `govulncheck` on every PR, plus weekly Dependabot updates for Go modules and GitHub Actions |
| Secret scanning | Gitleaks over the full Git history on every PR |
| Least-privilege CI | Workflow tokens default to `contents: read`, with write scopes granted per job only where needed |

## Reporting a vulnerability

Please **don't** open a public issue. Report privately through [GitHub Security Advisories](https://github.com/willj4945/cloudcomply/security/advisories/new). See [SECURITY.md](https://github.com/willj4945/cloudcomply/blob/main/SECURITY.md) for scope and response times.
