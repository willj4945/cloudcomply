# Command reference

```text
cloudcomply [--demo]                              launch the interactive dashboard
cloudcomply report nist [--format table|json]     print a NIST 800-53 report to stdout
cloudcomply completion <bash|zsh|fish|powershell> print a shell completion script
cloudcomply --version | --help
```

## Global flags

| Flag | Default | Description |
|---|---|---|
| `--demo` | `false` | Use the built-in sample dataset instead of calling AWS. Works on every command. |
| `--native-checks` | `false` | Also run cloudcomply's own AI workload checks in every account and region. Results roll up into the same NIST control rows as Security Hub findings. Needs the [assessor role](../aws/permissions.md#cross-account-native-checks) in member accounts. Ignored with `--demo`. |
| `--assume-role-name` | `cloudcomply-assessor` | Role that native checks assume in each member account |
| `--regions` | each account's enabled regions | Comma-separated regions for native checks, e.g. `us-gov-west-1` or `us-east-1,us-west-2`. Validated before any AWS call. |
| `-h`, `--help` | | Help for any command, e.g. `cloudcomply report nist --help` |
| `-v`, `--version` | | Print version, commit and build date |

## `cloudcomply`

Launches the [interactive dashboard](tui.md). Findings load in the background. The Security Hub fetch has a 30-second timeout. With `--native-checks`, each native-check call has its own 60-second timeout instead of one overall limit, because a large organization legitimately takes longer to scan.

## `cloudcomply report nist`

Prints a NIST SP 800-53 findings report without any interactive UI. This is the command to use in pipelines and scripts.

| Flag | Default | Description |
|---|---|---|
| `--format` | `table` | `table` for aligned human-readable columns, `json` for a stable machine-readable array (see [JSON schema](json-schema.md)) |

The format is checked **before** any AWS call, so a typo fails immediately.

### Table output

```console
$ cloudcomply report nist --demo
CONTROL   TITLE                              STATUS  SEVERITY  ACCOUNTS  RMF_STEP   MIN_IL
AC-2      Account Management                 FAILED  HIGH      12        Assess     IL2
AC-2(1)   Auto Temp/Emergency Accounts       PASSED  LOW       0         Monitor    IL4
AC-3      Access Enforcement                 PASSED  MEDIUM    0         Monitor    IL2
...
```

### JSON output

```console
$ cloudcomply report nist --demo --format json
[
  {
    "control_id": "AC-2",
    "title": "Account Management",
    "family": "AC",
    "status": "FAILED",
    "severity": "HIGH",
    "accounts_affected": 12,
    "rmf_step": "Assess",
    "min_impact_level": "IL2"
  },
  ...
]
```

Live results are sorted by `control_id`.

### Output streams

- **stdout** carries only the report, so it's safe to pipe into `jq` or redirect to a file.
- **stderr** carries only error messages.

## `cloudcomply completion`

Generated by Cobra. See [Installation → Shell completion](../getting-started/installation.md#shell-completion).

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success. The report printed, or the TUI exited normally. |
| `1` | Any error: invalid flag value, missing or invalid AWS credentials, AccessDenied, timeout, or an unknown command. The message is on stderr. |

!!! note "Failed controls don't change the exit code"
    `report nist` exits `0` even when controls fail. Reporting the posture is its job, and deciding whether that posture is acceptable is up to your pipeline. To gate a build, use `jq`, as shown in [CI/CD and automation](automation.md).

## Environment variables

cloudcomply has no environment variables of its own. It reads the standard [AWS SDK variables](https://docs.aws.amazon.com/sdkref/latest/guide/settings-reference.html#EVarSettings), including:

| Variable | Purpose |
|---|---|
| `AWS_PROFILE` | Named or SSO profile to use |
| `AWS_REGION` | Region to query Security Hub in. **Required outside CloudShell.** |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` | Static or temporary credentials (prefer roles and SSO) |
| `AWS_ROLE_ARN` / `AWS_WEB_IDENTITY_TOKEN_FILE` | Web-identity federation (e.g. GitHub Actions OIDC, EKS IRSA) |
| `AWS_CA_BUNDLE` | Custom CA bundle for TLS-inspecting proxies |
| `HTTPS_PROXY` / `NO_PROXY` | Outbound proxy settings |

For GovCloud, set `AWS_REGION=us-gov-west-1` or `us-gov-east-1`. The SDK resolves the `aws-us-gov` partition endpoints automatically.

## Timeouts

Both the TUI and `report nist` stop waiting for Security Hub and Organizations after **30 seconds**. That is enough for typical organizations. If you hit it, see [Troubleshooting](../troubleshooting.md#timeouts).

With `--native-checks`, every individual native-check call is bounded at **60 seconds** (assuming the role, discovering regions, and each check in each account and region). At most 8 run at once. There's no overall limit, because scan time grows with accounts × regions. A call that times out becomes an `ERROR` result for that account and region only; the rest of the scan still reports.
